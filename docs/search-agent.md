# Stretch search agent: current proof of concept

Checkout sends the chosen food list, approximate IP or manually chosen origin, ZIP, and 1–10 mile radius to `POST /api/agent/search`. OpenStreetMap/Overpass discovers grocery locations, including chains and independent shops, without assuming they have a price source. The endpoint streams cached observations, AI planning status, retailer reports, and a final coverage result as newline-delimited JSON. A local Ollama model can plan synonym/brand queries and review candidate matches; it never sets prices. Deterministic validation handles currency, package matching, unit prices, source URLs, pagination, and totals.

`lib/retailer-scraper.ts` is the credential-free live Lidl US adapter. It checks robots rules for the exact search URL, parses public rendered product tiles, and returns USD package prices, sizes, source links, and retrieval timestamps. It has no selected-branch pricing. `lib/provider-prices.ts` has bounded Bright Data collection adapters for supported retailer catalogs, using licensed provider jobs, allowlisted product URLs, persistent job/cache records, and an account-budget reservation. Its results are **online advertised prices**, not verified local shelf prices. `lib/live-data.ts` has a separate official Kroger Products and Locations API adapter. Only a coordinate-matched branch may enter a branch-priced basket; its search follows `filter.start` pages until a short page or the configured three-page cap. `lib/grocery-feed.ts` accepts an optional authorized branch-specific supplier, documented in [grocery-price-feed.md](grocery-price-feed.md).

The frontend shows products by retailer, matching packages before alternatives, preserving missing-price reasons and the source timestamp. Unit prices derive only from a positive source price and parseable package size; unknown sizes remain unknown. A complete branch-priced basket is ranked by an actual round-trip OSRM route, vehicle MPG, and entered or reported gas price. A selected gas station is inserted after the grocery stop. Online listings and dated observations never enter that ranking. Routing may fail, and taxes, stock, promo eligibility, dietary suitability, and split-store live optimization remain unverified.

## Access needed to expand coverage

- **Kroger family:** create a Kroger developer application with Products and Locations access. Set server-only `KROGER_CLIENT_ID` and `KROGER_CLIENT_SECRET`. Provider request limits and the app's own 20 requests/minute cap may leave some products or branches unchecked; the UI must keep those incomplete.
- **Walmart, Target, Publix, ALDI, Costco, other chains:** obtain an official retailer integration or licensed dataset with permitted product/price use. The current Bright Data key plus configured retailer dataset IDs can produce online listings where supported; it does not prove local shelf prices. A branch-specific licensed feed can use `GROCERY_PRICE_FEED_URL` and optional `GROCERY_PRICE_FEED_KEY`.
- **Smaller local retailers:** either a retailer-provided catalog/feed or a supplier that covers that exact location is needed. OSM supplies its location, not its checkout prices.
- **AI and discovery:** local Ollama with `OLLAMA_SEARCH_MODEL` enables the current on-host agent. `OPENAI_API_KEY` optionally enables web source discovery; `BRIGHT_DATA_API_KEY` and `BRIGHT_DATA_SERP_ZONE` enable licensed search/collection. Keep all keys server-only and set provider spending caps.
- **Routing and fuel:** OSRM is used for driving distance. OSM supplies gas station locations but not pump prices; a selected station can use a configured reported quote or the user's entered gas price. `GOOGLE_MAPS_API_KEY` with `GOOGLE_PLACES_ENABLED=true` can add station discovery, not grocery pricing.

The provider architecture deliberately reports `retrieved`, `pending`, `failed`, `blocked`, or `unsupported` for each mapped retailer instead of generating a placeholder price. This is a working search proof of concept, not a guarantee of full catalog or all-store coverage. Paid provider and retailer-imposed limits can prevent complete pagination; those limits must be shown rather than hidden.
